# 06 · SQL interview practice (22 questions on this warehouse)

Every query below runs against the built warehouse and the result shown is the real output (regenerated by `olist sql`). **Try each question yourself first**: open a DuckDB shell with `duckdb warehouse/olist.duckdb` (or `olist sql 08` to run one file), write your answer, then compare.

Tables you can use: `core.fct_orders`, `core.fct_order_items`, `core.dim_customers`, `core.dim_products`, `core.dim_sellers`, `core.dim_date`, and the untouched `raw.*` tables. Column lists: [warehouse/models/marts/core/_core.yml](../../warehouse/models/marts/core/_core.yml).

DuckDB extras used here (and their equivalents elsewhere): `QUALIFY` filters on a window function (Snowflake/BigQuery/Databricks have it; in Postgres/SQL Server wrap the query in a CTE and filter `where rn = 1`); `count(*) filter (where ...)` is `sum(case when ... then 1 else 0 end)` in any database; `date_diff('day', a, b)` is `DATEDIFF(day, a, b)` in SQL Server.

## Q09
<a id="q09"></a>

**What share of customers ordered more than once? (Careful: customer_id is per ORDER in Olist; the real person is customer_unique_id, which the warehouse calls customer_key.)**  
*Level: medium · Concepts: two-level aggregation, the "wrong id" trap*

<details><summary>Show answer</summary>

```sql
with per_customer as (
    select customer_key, count(*) as orders
    from core.fct_orders
    where is_valid_sale
    group by 1
)
select count(*)                                              as customers,
       count(*) filter (where orders >= 2)                   as repeat_customers,
       round(100.0 * count(*) filter (where orders >= 2) / count(*), 2) as repeat_pct,
       max(orders)                                           as max_orders_by_one_customer
from per_customer;
```

Result:

|   customers |   repeat_customers |   repeat_pct |   max_orders_by_one_customer |
|------------:|-------------------:|-------------:|-----------------------------:|
|   94,990.00 |           2,888.00 |         3.04 |                        16.00 |

**Takeaway:** Only ~3% of customers ever return. Counting customer_id instead would report 0% repeat, because Olist issues a new customer_id for every order.

</details>

## Q10

**For customers who came back, how many days passed between their 1st and 2nd order?**  
*Level: medium · Concepts: ROW_NUMBER to number each customer's orders, self-join (or LEAD), percentiles*

<details><summary>Show answer</summary>

```sql
with numbered as (
    select customer_key, purchased_at,
           lead(purchased_at) over (partition by customer_key order by purchased_at) as next_at,
           row_number()       over (partition by customer_key order by purchased_at) as n
    from core.fct_orders
    where is_valid_sale
)
select count(*)                                                               as customers_with_2nd_order,
       round(avg(date_diff('day', purchased_at, next_at)), 1)                 as avg_days,
       quantile_cont(date_diff('day', purchased_at, next_at), 0.5)            as median_days,
       round(100.0 * avg((date_diff('day', purchased_at, next_at) = 0)::int), 1) as pct_same_day
from numbered
where n = 1 and next_at is not null;
```

Result:

|---------------------------:|-----------:|--------------:|---------------:|
|                   2,888.00 |      80.80 |         28.00 |          30.10 |

## Q13
<a id="q13"></a>

**How many sellers (and what % of sellers) together make 80% of item revenue?**  
*Level: hard · Concepts: cumulative share with a window, then pick the first row that crosses 80%*

<details><summary>Show answer</summary>

```sql
with s as (
    select seller_id, sum(item_price) as revenue
    from core.fct_order_items
    where is_valid_sale
    group by 1
), ranked as (
    select seller_id, revenue,
           row_number() over (order by revenue desc)                         as rnk,
           sum(revenue) over (order by revenue desc rows unbounded preceding)
             / sum(revenue) over ()                                          as cum_share,
           count(*) over ()                                                  as n_sellers
    from s
)
select rnk                               as sellers_needed,
       n_sellers,
       round(100.0 * rnk / n_sellers, 1) as pct_of_sellers,
       round(100 * cum_share, 2)         as cum_revenue_pct
from ranked
where cum_share >= 0.8
order by rnk
limit 1;
```

Result:

|   sellers_needed |   n_sellers |   pct_of_sellers |   cum_revenue_pct |
|-----------------:|------------:|-----------------:|------------------:|
|           540.00 |    3,053.00 |            17.70 |             80.02 |

**Takeaway:** ~18% of sellers make 80% of item revenue (the dbt mart says 558 sellers using items + freight; 540 here on items only: always state which revenue definition you used).

</details>

## Q14
<a id="q14"></a>

**Build a monthly cohort table: for customers whose first order was in month X, what % ordered again 1, 2 and 3 months later? (First-half 2017 cohorts.)**  
*Level: hard · Concepts: cohort assignment with MIN() OVER, month difference, conditional aggregation into columns (pivot)*

<details><summary>Show answer</summary>

```sql
with o as (
    select customer_key, purchase_month,
           min(purchase_month) over (partition by customer_key) as cohort_month
    from core.fct_orders
    where is_valid_sale
), activity as (
    select distinct customer_key, cohort_month,
           date_diff('month', cohort_month, purchase_month) as months_since
    from o
)
select cohort_month,
       count(distinct customer_key) filter (where months_since = 0)                       as cohort_size,
       round(100.0 * count(distinct customer_key) filter (where months_since = 1)
             / count(distinct customer_key) filter (where months_since = 0), 2)           as m1_pct,
       round(100.0 * count(distinct customer_key) filter (where months_since = 2)
             / count(distinct customer_key) filter (where months_since = 0), 2)           as m2_pct,
       round(100.0 * count(distinct customer_key) filter (where months_since = 3)
             / count(distinct customer_key) filter (where months_since = 0), 2)           as m3_pct
from activity
where cohort_month between '2017-01-01' and '2017-06-01'
group by 1
order by 1;
```

**Some orders have several reviews in the raw data. Keep only the most recently answered review per order and show how many rows that removes.**  
*Level: medium · Concepts: deduplication with ROW_NUMBER, the most common data-cleaning pattern in SQL interviews*

<details><summary>Show answer</summary>

```sql
with ranked as (
    select *,
           row_number() over (partition by order_id
                              order by review_answer_timestamp desc, review_creation_date desc, review_id) as rn
    from raw.order_reviews
)
select count(*)                          as raw_rows,
       count(*) filter (where rn = 1)    as deduped_rows,
       count(*) filter (where rn > 1)    as removed,
       count(distinct order_id)          as distinct_orders
from ranked;
```

|-----------:|---------------:|----------:|------------------:|

## Q16
<a id="q16"></a>

**Find orders that have no items at all, grouped by status. Two ways: LEFT JOIN ... IS NULL, and NOT EXISTS.**  
*Level: easy · Concepts: anti-join*

<details><summary>Show answer</summary>

```sql
select o.order_status, count(*) as orders_without_items
from raw.orders o
left join raw.order_items i on i.order_id = o.order_id
where i.order_id is null
group by 1
```

## Q17
<a id="q17"></a>

**Reconcile payments against items + freight. How many valid orders differ by more than R$1, and what is the typical gap? (Data-quality check that finance teams run.)**  
*Level: hard · Concepts: aggregating two child tables separately BEFORE joining (joining first would multiply rows)*

<details><summary>Show answer</summary>

```sql
with items as (
    select order_id, sum(price + freight_value) as items_total
    from raw.order_items group by 1
), pays as (
    select order_id, sum(payment_value) as paid
    from raw.order_payments group by 1
)
select count(*)                                                    as orders_compared,
       count(*) filter (where abs(paid - items_total) > 1)         as mismatched,
       round(100.0 * count(*) filter (where abs(paid - items_total) > 1) / count(*), 2) as mismatched_pct,
       round(median(paid - items_total) filter (where abs(paid - items_total) > 1), 2)  as median_gap
from items join pays using (order_id)
join raw.orders o using (order_id)
where o.order_status not in ('canceled', 'unavailable');
```

Result:

|   orders_compared |   mismatched |   mismatched_pct |   median_gap |
|------------------:|-------------:|-----------------:|-------------:|
|         98,198.00 |       247.00 |             0.25 |         6.98 |

**Takeaway:** 0.25% of orders don't reconcile; the warehouse tracks this with a dbt test set to warn (not fail), because interest on installments and vouchers explain most gaps.

**For each region, the category with the 2nd-highest revenue (the classic "Nth highest" question).**  
*Level: medium · Concepts: DENSE_RANK vs ROW_NUMBER vs RANK (ties), join to a dimension for the region*

```sql
with r as (

qualify dense_rank() over (partition by region order by revenue desc) = 2
order by region;
```
